`app/.env.dokploy.prod.old` and `landing/.env.dokploy.prod.old`. Their contents are
preserved. The preferred handoff is now the complete, ignored, mode-0600 file

The smaller `.env.dokploy.app` and `.env.dokploy.landing` files documented below

## Automatic database rollout

The Docker image packages all committed migrations and the locked migration CLI.
Its unprivileged entrypoint applies migrations before starting the server; a build
does not access the database. The prepared changes and the merged upstream add seven migrations:

- `20261103120000_translation_market_fit`
- `20261104010000_ai_allowances_custom_seats`
- `20261104020000_paid_subscription_period`
- `20261104030000_ai_invoice_receipts`
- `20261104040000_onboarding_recovery`
- `20261104050000_onboarding_trial_deadline`
- `20261104120000_api_keys`

They add billing/allowance state, a system-only signup recovery record, translation
market-fit metadata and scoped API keys. They do not reset data, reprice existing
subscriptions or automatically buy anything.
Migration credentials must permit the committed DDL. A failed migration stops the
container; do not resolve arbitrary failed migrations as applied without inspection.

The upstream API-key migration hashes existing plaintext keys into read-only
`ApiKey` records and drops `ClientSite.apiKey`. Old application images query that
column and are incompatible with the migrated schema: stop old replicas before
applying this migration and do not roll back only the image afterward. Review this
deployment ordering before an automatic rollout; an image build does not test
overlapping old and new production replicas. The published migration is retained
unchanged, including for environments where the colleague already applied it.

## Upstream integration, 2026-11-05

The merged commercial allowance is PRO 50 and PREMIUM/managed CUSTOM 100 article
units per month. STANDARD/HIGH/ULTRA still cost 1/2/3 units. Prices, the 15% base
revenue funding target, the USD 1 trial cap and explicit top-up rules are unchanged.
Existing grant records retain their stored amounts. The landing displays these
same counts and distinguishes article units from shared provider capacity.

Private API draft/status reads and queued generation revalidate the creating
member's current permissions and team seat. GENERATE can request a draft without
granting general WRITE/PUBLISH access. Unknown idempotency outcomes retain their
claim rather than retrying a potentially committed operation; only known client
rejections release it. SMART translation assessment uses the blog's funding and
defers exhausted work instead of bypassing the assessment through its fallback.

## Provider configuration and product behavior

Read-only live inspection verified nine active USD Prices, their Products and
recurrence, the configured Customer Portal and the current active webhook's event
subscriptions. No live Stripe object was changed during this preparation.
The existing active webhook and its primary signing secret remain usable. The
staged Basil endpoint remains disabled; adding its secondary secret does not enable
it. An optional, operator-controlled version migration is documented in
[the catalog rollout](stripe-catalog-rollout.md); it is separate from this release.

The release retains BASIC/PRO/PREMIUM team limits of 1/2/3, including the owner.
Managed CUSTOM starts at three seats: USD 159 base plus two USD 20 members, USD 199
monthly or USD 1,910.40 annually. Additional CUSTOM capacity requires an explicit
confirmed billing action; invitations never authorize a charge. Old individual
CUSTOM contracts remain unchanged.

Subscriptions, trial and allowances belong to each blog. Further blogs are BASIC
and do not create repeat trials. AI exhaustion stops work; it never adds an
automatic overage charge. Customers can explicitly buy the existing article packs
or the configured usage packs. See [the policy](ai-economics-proposal.md) for exact
allowances, purchased balances, provider reservations and limits of cost estimates.
No paid whole-article cost calibration was performed, so actual gross margin is
not certified by these checks.

Signup recovery uses the existing stable `AUTH_SECRET`, original verified details,
database leases and Stripe idempotency keys. It resumes partial completion without
another account or trial. Consumed/expired login links are not renewed. After an
expired Checkout, a later signed-in billing action, or an uncertain mutation older
than 23 hours, the user proceeds through ordinary sign-in and billing instead.
